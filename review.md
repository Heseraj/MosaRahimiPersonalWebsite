## 3. Critical findings

### C1 — The Digital Twin is broken on the live site

**Severity: Critical. This is the single most urgent item, and the one item with prescribed fix steps.**

The live endpoint returns:

```
POST https://mosarahimi.com/api/chat
HTTP 503
{"error":"The Digital Twin is not configured yet."}
```

A `GET` to the same path returns 405, which confirms the route handler *is* deployed and reachable — Next.js correctly rejects the wrong method. So the code shipped fine. The 503 comes from your own guard clause in `app/api/chat/route.ts`:

```ts
const apiKey = process.env.OPEN_ROUTER_API_KEY;

if (!apiKey) {
  return Response.json(
    { error: "The Digital Twin is not configured yet." },
    { status: 503 },
  );
}
```

**Root cause.** `OPEN_ROUTER_API_KEY` is not set in the Vercel environment.

This is a side effect of doing the secret handling *correctly*. `.gitignore` excludes `.env`, which is right — I confirmed via a search of all commits that the key was never committed. But because the file never reaches the repository, it never reaches Vercel either. Vercel requires environment variables to be set separately in project settings. The deployed function reads `process.env.OPEN_ROUTER_API_KEY`, finds nothing, and short-circuits to 503 before it ever contacts OpenRouter.

**Why this is critical rather than merely a bug.** The failure is loud and it is on your most prominent call to action:

- The header button reads "Ask my AI twin" and is the primary CTA.
- The section headline promises "A career you can question."
- The chat renders a warm opening message and four inviting suggestion buttons.
- Clicking any of them produces an error.

A recruiter's most likely path through this site is: read the hero, click the AI twin CTA (it is the most novel thing on the page), click a suggested question, get an error. The feature that was meant to differentiate you is currently the feature that demonstrates something shipped broken.

#### Fix

1. In the Vercel dashboard, go to **Project → Settings → Environment Variables**.
2. Add `OPEN_ROUTER_API_KEY` with your OpenRouter key.
3. Scope it to **Production** (and **Preview** if you want preview deployments working).
4. **Redeploy.** Vercel does not apply new environment variables to an existing build — the current deployment will keep returning 503 until a new one is triggered.

Before you do this, set a **hard spend limit on the OpenRouter key itself** in the OpenRouter dashboard. The endpoint currently returns a free 503; the moment the key is live it begins making billable calls on a public URL. A per-key credit cap takes a minute and is the only control that cannot be bypassed by an application-level bug.

#### Verify the fix

```bash
curl -s -X POST https://mosarahimi.com/api/chat \
  -H "Content-Type: application/json" \
  -d '{"messages":[{"role":"user","content":"Who are the Hazara people?"}]}'
```

A correctly configured deployment returns `{"answer":"..."}`. If it still returns 503, the redeploy did not pick up the variable.

#### Prevent a silent recurrence

From a visitor's side, a missing key looks identical to a service outage, so this can break again without you noticing. Two options, in order of preference:

1. **Graceful fallback.** Have the section detect the unconfigured state and render a short note that the twin is offline, plus your LinkedIn link — rather than an interactive chat box that errors on click. This turns a broken feature into a neutral one.
2. **Monitoring.** At minimum, add an uptime check that POSTs to `/api/chat` periodically, so you learn about a failure before a recruiter does.

Also worth noting: `README.md` documents only local setup and makes no mention of the Vercel deployment or the required production environment variable. Documenting the deploy step would likely have prevented this.

### H2 — Once the API key is set, the abuse and cost controls will not hold

Currently mitigated only by the fact that the key is missing (C1). This is the reason C1's fix steps include setting a spend cap on the key.

**The rate limiter cannot work on Vercel.** `app/api/chat/route.ts` stores counters in a module-level `Map`:

```ts
const requestLog = new Map<string, number[]>();
```

Vercel runs this route as serverless functions. Each instance gets its own memory, instances scale horizontally under load, and they are recycled freely. The intended limit of 15 requests per 10 minutes is therefore *15 per instance* — the effective ceiling is unbounded, and it resets on every cold start. An attacker does not need to do anything clever.

**The fallback identifier collapses all visitors into one bucket.**

```ts
const identifier = forwardedFor?.split(",")[0]?.trim() || "local";
```

Any request without `x-forwarded-for` is counted as `"local"`. On Vercel the header is normally present, but every request that lacks it shares a single 15-request budget — so a handful of such requests can lock out legitimate visitors.

**The key is trivially spoofable.** `x-forwarded-for` is client-supplied. Rotating a header value defeats the limiter entirely, independent of the instance problem.

**The Map never evicts.** Identifiers are added and their timestamp arrays filtered, but keys whose arrays become empty are never deleted. Long-lived processes leak memory slowly. Minor next to the above, but it is a real leak.

**No absolute spend ceiling.** Per request you allow up to 12 messages × 1600 characters (~19K characters, roughly 5K tokens) plus a system prompt of roughly 2.5K tokens, with `max_tokens: 800`. With a working key and no effective limiter, a script can burn your OpenRouter credits on a personal site with no revenue.

## 6. Medium-priority findings

**M1 — `crypto.randomUUID()` will throw over LAN.** `components/digital-twin-chat.tsx` calls it for every message ID. It is only available in secure contexts. `localhost` and HTTPS are fine, so both `npm run dev` locally and production work. But `next dev` prints a Network URL like `http://192.168.x.x:3000`, and if you open that on your phone to demo the site, `crypto.randomUUID` is undefined and every send throws.

**M2 — No streaming.** With `max_tokens: 800` and a 60-second timeout, a visitor can wait many seconds looking at three animated dots. Streaming would be the single largest perceived-quality win available for this feature.

**M3 — No way to cancel a request.** `ask()` has no `AbortController`. A user cannot stop a slow generation, and if the component unmounts mid-flight the state updates land on an unmounted component. React 19 tolerates this without warning, but the request still runs and still bills.

**M4 — `HTTP-Referer` is hardcoded to localhost.** `route.ts` sends `"HTTP-Referer": "http://localhost:3000"`. Since the site is live, all production usage is attributed to localhost in OpenRouter's dashboard. (The `X-OpenRouter-Title` header is correct — I verified it against OpenRouter's current docs; `X-Title` is the legacy alias.)

**M5 — Typography includes unreadable sizes.** 37 font-size declarations in `globals.css` are 10px or below, including **7px** (lines 1221, 2277) and **8px** (lines 1203, 1431, 1669, 1856, 2017, 2250, 2346). 7px is not readable by most people. Many of these are also uppercase with wide letter-spacing on translucent white, which compounds the problem. I did not measure contrast ratios. Some are decorative (the `01 / 05` index, watermarks), which is defensible — the labeled captions and eyebrows are not.

**M6 — `aria-live` covers the whole conversation.** `.twin-messages` carries `aria-live="polite"`, so a screen reader may re-announce the entire transcript on each update instead of just the new message.

**M7 — `aria-labelledby` and `aria-label` on plain `<div>`s do nothing.** `.father-story`, `.work-story`, `.mission-story`, `.education-story` all set `aria-labelledby`, and `.story-photo-spread` sets `aria-label`, but a generic `div` has no role, so assistive technology ignores these. Currently these are accessibility annotations that read as correct but have no effect.

**M8 — Image payload is heavy in the repository.** `WhartonMBA_H3_0354.jpg` is **16.2 MB**; `Full Family Iran.jpg` is 6.7 MB; `Family After Grandma.jpg` is 5.47 MB. Total across 14 images is roughly 38.6 MB. Next optimizes what it *serves*, so visitor experience is fine — the costs are repository size, clone time, and build time spent processing a 16 MB JPEG.

**M9 — Story numbering is inconsistent.** Labels run "Story 02" (father), "Story 03" (work), "Story 04" (mission), "Story 05" (education). There is no "Story 01" — the childhood photo spread is unlabeled. Meanwhile `.father-story-mark` renders a decorative "01" inside the section labeled "Story 02," and the hero portrait index reads "01 / 05." A reader who notices the numbering finds it broken.

**M10 — No tests, and no test script.** `package.json` has `dev`, `build`, `start`, `lint`. For a personal site this is a defensible tradeoff, but two pure functions in the API route carry real correctness risk and are trivial to test: `parseMessages` (nine distinct rejection paths) and `isRateLimited` (window arithmetic).

**M11 — `.sr-only` works only by accident of Tailwind's scanner.** The class is used three times in `digital-twin-chat.tsx` and is never defined in `globals.css`. I confirmed it *is* present in the compiled CSS, generated by Tailwind v4's automatic content detection. But Tailwind is otherwise essentially unused — the site is ~2,771 lines of hand-written CSS. So a dependency you might reasonably think is dead is in fact load-bearing for screen-reader text, and removing it would silently make hidden labels visible. Right now it is correct by coincidence.

**M12 — `globals.css` is a 2,771-line monolith.** Per-section bespoke rules with no clear token discipline, and at least one duplicated selector block. It builds fine and the visual result is good, but this is the file that will resist change six months from now.

**M13 — No security headers.** The live response includes HSTS (Vercel default) but no `Content-Security-Policy`, `X-Content-Type-Options`, `Referrer-Policy`, or `X-Frame-Options`. `next.config.ts` only sets `poweredByHeader: false`. For a brochure site the practical risk is low. Also worth noting: the homepage returns `Access-Control-Allow-Origin: *`, which is harmless for public HTML but worth confirming is not applied to `/api/chat`.

**M14 — Assets live in the project root.** Fourteen images plus the résumé PDF sit alongside `package.json` and `tsconfig.json`, imported via `../Full Family Iran.jpg`. This works, but it clutters the root and makes imports fragile. Since these are statically imported rather than served, they are not `public/` candidates.

**M15 — Filename typos are visible in source and in a public repo.** `Dugst and greese on my clothes.jpg` ("Dust and grease"), `Mission to the sout 1.jpg` and `Mission to the sout 2.jpeg` ("south"), `Wharton After Graduatioin Ceremoney.jpeg` (two typos), and `AUAF Graduation Day .jpeg` (trailing space before the extension). These appear as import specifiers in `page.tsx`. Cosmetic, but they are in a public repository attached to your professional identity, and spaces in import paths are needlessly fragile.

## 9. Closing assessment

The build quality here is not the problem. Lint, types, and the production build are all clean; the API route is more carefully validated than most production code I see; the secret handling is correct in every particular; and the writing in the story sections is genuinely strong and specific in a way that most career sites never manage.

What needs attention is the gap between what the site claims and what a motivated reader finds when they check. That gap appears in three places: a flagship AI feature that errors on click, a "Technical work" section that invites inspection of a repository containing course handouts, and a set of career claims that drift consistently in the direction of more rather than less.

The pattern connecting all three is worth naming, because it is the same judgment you already exercised well once. You removed the certifications because the distance between "Wharton MBA, Harvard MPA" and "Programming Foundations: Fundamentals" read as a credibility gap. That instinct was right. C2 and C3 are the same gap in different clothing — and the site is live, so they are being read now.

The encouraging part is that the honest versions of these claims are still strong. A six-year self-directed venture pursued while earning two graduate degrees, MBA internships in refugee-focused energy and investment, a survey directorship, a promotion inside Amazon in seven months, and a decade of Afghan public service under real risk — that is a remarkable record that needs no embellishment. Removing the overstatements costs you very little and buys you the one thing this site is actually selling, which is that you can be trusted about what you know and what you do not.
